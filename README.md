## 先分清你要的是哪一种"爬虫服务器"

这个词至少对应三种完全不同的东西，买错了钱就浪费在没用的配置上。

**第一种，现成的爬虫接口服务。** 你不想写解析逻辑，直接用 HTTP 调别人的接口拿数据。适合固定几个平台、字段需求标准、量不大的场景。不适合需要私有字段、需要深度定制清洗、或者平台不在支持列表里的项目。

**第二种，自建采集加自建代理池。** 你自己写 Scrapy 或 aiohttp，配一套代理池轮换 IP。适合目标站点多、字段自己定、量能撑起运维成本的项目。不适合一周只跑一次、总共几万条的任务，那时候养代理池的精力比写爬虫还多。

**第三种，分布式采集集群。** 多台机器共用一个 Redis 存请求队列和统计，随时加机器扩并发。适合长期跑、日增量上百万条的项目。个人项目基本用不到。

SixtyNet 这类 VPS 属于第二种和第三种的基础设施。它不提供爬虫能力，只提供一台有特定 IP 属性和大流量的机器。

## 自建代理池要养两个进程，还得有一台 7×24 挂着的机器

ProxyPool 是这类项目里文档最全的一个，也最能说明"自建"的真实成本。

它不是跑一个进程就完事。`schedule` 调度程序负责采集代理、验证、维护池子；`server` API 服务基于 Flask，对外提供取代理的 HTTP 接口，默认监听 **5010** 端口。两个都要常驻。

调度频率写死在代码里：启动时立即采集一次，之后 `proxy_fetch` 每 5 分钟采集，`proxy_check` 每 2 分钟校验，底层是 APScheduler 的 `BlockingScheduler`。

几个默认参数决定了这台机器要有多稳：

- `POOL_SIZE_MIN = 20`，校验任务开跑前池里少于 20 个代理就先触发抓取
- `MAX_FAIL_COUNT = 0`，校验失败一次直接剔除，不给第二次机会
- `VERIFY_TIMEOUT = 10` 秒，超时即判定不可用
- `DB_CONN = 'redis://:密码@127.0.0.1:6379/0'`，支持 redis 和 ssdb

启动即退出的头号原因是数据库：启动前 `__beforeStart()` 会调 `db.test()` 校验连接，连不上直接 `exit` 退出进程。所以机器上必须先有 Redis，且密码、端口、db 编号都对。

还有一个文档坑值得单独说：README 示例里曾出现 5000 端口，当前 `setting.py` 的默认值已经统一成 5010，API 文档的示例也以 5010 为准。照着旧教程敲 `curl http://127.0.0.1:5000/get/` 会连不上，不是服务没起来。

运行环境是 Python 3.8 到 3.11。配置优先级为环境变量高于 `setting.py`，所以 Docker 传参能生效。验证是否跑起来，用 `curl http://127.0.0.1:5010/count/` 和 `curl http://127.0.0.1:5010/get/`；池子为空时得等首轮采集校验完。

对选机器的含义很直接：你需要一台能长期稳定跑两个 Python 进程加一个 Redis 的机器，内存 2G 是下限，磁盘不大但要稳，网络不能时断时续。LAX-STARTER 这个档位刚好卡在这条线上。

## 并发参数决定的是带宽和 IP，不是核心数

生产级爬虫的配置单能反过来告诉你该买什么机器。

Scrapy 的生产配置是全局并发 32、单域名并发 8、`DOWNLOAD_DELAY = 0.5`，开启 AutoThrottle 且目标并发 16、最大延迟 60 秒。异步方案里，页面请求 `timeout=15`、详情页 `timeout=10`、`max_retries=3`，遇到 429 限流用 `2**i` 指数退避，也就是 1 秒、2 秒、4 秒依次重试。超时或代理连接失败，会把该代理从池里移除。

32 个并发连接在 CPU 上几乎看不出负载，2 核绰绰有余。真正吃紧的是出站带宽和 IP 质量。这也是为什么 SixtyNet 的套餐配置里，带宽写的是 2G、4G、10G，流量写的是 5TB 到 40TB，而不是堆 CPU 核心。

流量够不够，可以粗算。按每页 HTML 200KB 算，5TB 大约是 2500 万次页面请求的量级；把图片和附件算进去按 500KB 一页，也有 1000 万次。日采 10 万页的项目，一个月大约用掉 600GB，只占 5TB 的 12%。对多数中等规模项目，流量不是瓶颈，IP 才是。

## 常见问题

**IP 被风控了怎么办？**

先判断是频率问题还是 IP 属性问题。降并发、加延迟、开 AutoThrottle 能解决前者。如果请求量已经压得很低还是 403，那就是 IP 段被标记了，换机房 IP 解决不了，得换住宅 IP 段。这也是 SixtyNet 住宅系列相对 LAX 系列的差价所在。

**一台机器能不能同时跑爬虫和代理池？**

能。两个 Python 进程加一个 Redis，2 核 2G 是下限，跑起来内存会紧但不会崩。如果要同时跑 Scrapy 集群加 MySQL 加 Elasticsearch，就得往上走一档到 LAX-MICRO 或 LAX-MEDIUM。注意住宅 IP 那组不开放 80 和 443，如果你的爬虫带 Web 管理界面，得改端口。

**跑开源的爬虫接口服务需要什么环境？**

Python 加 Node.js 两个运行时，默认 8080 端口。首次使用必须先调 `add_account` 接口添加账号 cookie，否则所有请求都会失败。日志在 `.log/crawler.log`。

**买了住宅 IP 的机器，还要不要代理池？**

看你爬多少。单机单 IP 跑小规模任务，住宅 IP 本身的属性就够了。日请求量上到几万次、目标站点风控严，还是要配代理池轮换，否则一个 IP 再干净也会被频率规则拦下来。
